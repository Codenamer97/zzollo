# 요구사항 정의서

## 1. 문서 개요

### 1.1 문서명

**WinForms 기반 Ollama 연동 로컬/사내망 AI 코드 분석 도구 요구사항 정의서**

### 1.2 목적

본 프로젝트는 사용자의 로컬 PC 또는 사내망 내 다른 PC에서 실행 중인 Ollama LLM을 활용하여, 사용자가 선택한 C# 프로젝트 폴더 및 관련 파일을 분석하고, 사용자의 질문에 대해 코드 리뷰, 개선 제안, 오류 가능성 분석, 리팩토링 방향 등을 제공하는 WinForms 기반 데스크톱 애플리케이션을 개발하는 것을 목적으로 한다.

### 1.3 개발 방향

본 프로그램은 단순한 “채팅 프로그램”이 아니라, **개발자가 자신의 프로젝트 폴더를 선택하고, 해당 프로젝트의 파일 내용을 기반으로 Ollama에게 질문할 수 있는 로컬 AI 개발 보조 도구**를 목표로 한다.

Ollama는 기본적으로 HTTP API를 제공하며, 로컬 실행 시 기본 주소는 `http://localhost:11434/api`이다. `/api/chat` 엔드포인트는 채팅 메시지를 모델에 전달하는 용도로 사용되며, `stream: false` 설정으로 일반 JSON 응답을 받을 수 있다. ([Ollama Docs][1])

# 3. 전체 시스템 개념

## 3.1 기본 동작 흐름

```txt
사용자
→ WinForms 앱 실행
→ 프로젝트 폴더 선택
→ 앱이 파일 목록 수집
→ 사용자가 질문 입력
→ 앱이 관련 파일 내용과 질문을 조합
→ Ollama API 호출
→ Ollama 답변 수신
→ WinForms 화면에 답변 표시
```

## 3.2 Ollama 연결 방식

본 프로그램은 두 가지 연결 방식을 지원해야 한다.

| 탭   | 연결 대상               | 예시                          |
| --- | ------------------- | --------------------------- |
| 탭 1 | 로컬 PC의 Ollama       | `http://localhost:11434`    |
| 탭 2 | 사내망 내 다른 PC의 Ollama | `http://192.168.0.50:11434` |

Ollama의 API는 기본적으로 HTTP 방식으로 호출 가능하며, 로컬 API 접근에는 별도 인증이 필요하지 않다. 다만 원격 PC에서 Ollama에 접근하는 경우에는 방화벽, 네트워크 바인딩, 사내 보안 정책을 별도로 고려해야 한다. ([Ollama Docs][2])

# 5. 탭별 요구사항

## 5.1 탭 1: Local Ollama

### 5.1.1 목적

현재 사용자의 PC에서 실행 중인 Ollama를 사용하여 프로젝트 파일을 분석한다.

### 5.1.2 기본 연결 정보

| 항목           | 기본값                      |
| ------------ | ------------------------ |
| Host         | `localhost`              |
| Port         | `11434`                  |
| Base URL     | `http://localhost:11434` |
| API Endpoint | `/api/chat`              |

### 5.1.3 UI 항목

| UI 항목           | 필수 여부 | 설명                                          |
| --------------- | ----: | ------------------------------------------- |
| 모델명 입력 ComboBox |    필수 | 예: `llama3.1`, `qwen2.5-coder`, `codellama` |
| 연결 테스트 버튼       |    필수 | Ollama 서버 응답 확인                             |
| 모델 목록 조회 버튼     |    권장 | 사용 가능한 모델 목록 표시                             |
| Temperature 입력  |    권장 | 답변 창의성 조정                                   |
| Timeout 설정      |    권장 | 응답 제한 시간 설정                                 |
| Stream 응답 여부    |    선택 | 실시간 응답 출력 여부                                |

### 5.1.4 동작 요구사항

1. 사용자는 로컬 Ollama 연결 테스트를 수행할 수 있어야 한다.
2. 연결 실패 시 명확한 오류 메시지를 표시해야 한다.
3. 모델명이 비어 있을 경우 요청을 차단해야 한다.
4. 기본 모델명은 설정 파일에서 관리할 수 있어야 한다.

---

## 5.2 탭 2: Remote Ollama

### 5.2.1 목적

사내망 내 다른 컴퓨터에서 실행 중인 Ollama를 사용하여 프로젝트 파일을 분석한다.

### 5.2.2 UI 항목

| UI 항목           | 필수 여부 | 설명                    |
| --------------- | ----: | --------------------- |
| IP 입력 TextBox   |    필수 | 예: `192.168.0.50`     |
| Port 입력 TextBox |    필수 | 기본값 `11434`           |
| 모델명 입력 ComboBox |    필수 | 원격 Ollama에서 사용할 모델명   |
| 연결 테스트 버튼       |    필수 | 원격 Ollama 접속 가능 여부 확인 |
| 서버 별칭 입력        |    권장 | 예: `개발팀 GPU PC`       |
| 최근 서버 목록        |    권장 | 최근 접속한 IP/Port 저장     |
| Timeout 설정      |    권장 | 원격 응답 지연 대비           |
| 보안 경고 표시        |    필수 | 원격 서버로 코드가 전송됨을 명시    |

### 5.2.3 보안 요구사항

원격 Ollama 사용 시 반드시 다음 경고를 표시해야 한다.

```txt
주의: 원격 Ollama 사용 시 선택한 코드 파일 내용이 사내망의 다른 PC로 전송됩니다.
민감 정보, 비밀번호, API Key, 개인정보가 포함되어 있지 않은지 확인하십시오.
```

이건 무조건 넣어야 한다.
코드 분석 도구에서 보안 경고 없이 원격 전송을 허용하는 건 설계상 좋지 않다.

# 7. 파일 선택 및 분석 방식 요구사항

## 7.1 분석 범위 선택

사용자는 Ollama에게 보낼 분석 범위를 선택할 수 있어야 한다.

| 분석 범위       | 설명                                                          |
| ----------- | ----------------------------------------------------------- |
| 현재 선택한 파일만  | 단일 파일 리뷰                                                    |
| 체크한 파일들     | 사용자가 선택한 여러 파일 리뷰                                           |
| 주요 파일 자동 선택 | `.sln`, `.csproj`, `Program.cs`, `Form.cs`, `Service.cs` 우선 |
| 전체 프로젝트 요약  | 파일별 요약 후 전체 분석                                              |
| 사용자 지정 확장자  | 특정 확장자만 포함                                                  |

## 7.2 전체 프로젝트 분석 방식

전체 프로젝트를 한 번에 Ollama에 보내면 안 된다.
컨텍스트 초과, 응답 품질 저하, 속도 저하 문제가 발생한다.

따라서 전체 프로젝트 분석은 다음 방식으로 처리해야 한다.

```txt
1. 프로젝트 파일 목록 수집
2. 파일 크기와 확장자 기준으로 필터링
3. 파일별 요약 생성
4. 요약 결과를 누적
5. 누적 요약을 기반으로 최종 프로젝트 분석 요청
```

## 7.3 파일 크기 제한

| 항목               |            기본값 |
| ---------------- | -------------: |
| 단일 파일 최대 크기      |          100KB |
| 1회 요청 최대 포함 파일 수 |            10개 |
| 1회 요청 최대 문자 수    |          설정 가능 |
| 초과 파일 처리         | 제외 또는 요약 모드 전환 |

# 8. Ollama 호출 요구사항

## 8.1 API 방식

기본 호출 방식은 HTTP API를 사용한다.

| 항목          | 내용                   |
| ----------- | -------------------- |
| 방식          | HTTP POST            |
| 기본 Endpoint | `/api/chat`          |
| 응답 방식       | 기본 `stream: false`   |
| 요청 형식       | JSON                 |
| 응답 처리       | `message.content` 추출 |

Ollama의 `/api/chat`은 모델명과 메시지 배열을 전달하여 채팅 응답을 생성한다. 기본적으로 스트리밍 방식이지만, `stream: false`를 지정하면 하나의 JSON 응답으로 받을 수 있다. ([GitHub][3])

## 8.2 요청 데이터 구성

요청에는 최소 다음 정보가 포함되어야 한다.

```json
{
  "model": "llama3.1",
  "stream": false,
  "messages": [
    {
      "role": "system",
      "content": "너는 C# 코드 리뷰 전문가다."
    },
    {
      "role": "user",
      "content": "사용자 질문 및 코드 내용"
    }
  ]
}
```

## 8.3 System Prompt 기본값

기본 시스템 프롬프트는 다음 내용을 포함해야 한다.

```txt
너는 30년차 C#/.NET 개발팀장급 코드 리뷰어다.

다음 기준으로 분석한다.
- 컴파일 오류 가능성
- 런타임 오류 가능성
- 예외 처리 누락
- async/await 오용
- WinForms UI Thread 문제
- 메모리 누수 가능성
- IDisposable 처리
- 성능 문제
- 보안 문제
- 유지보수성
- 네이밍
- 중복 코드
- 설계 구조

확실하지 않은 내용은 추측하지 말고 "추가 확인 필요"라고 표시한다.
수정 제안이 있으면 가능한 한 C# 코드 예시를 제공한다.
```

## 10.2 민감정보 탐지

Ollama에 전송하기 전 다음 패턴을 검사해야 한다.

| 항목         | 예시                                  |
| ---------- | ----------------------------------- |
| API Key    | `api_key`, `apikey`, `access_token` |
| 비밀번호       | `password`, `pwd`, `secret`         |
| DB 연결 문자열  | `Server=`, `User Id=`, `Password=`  |
| JWT Secret | `Jwt:Secret`, `IssuerSigningKey`    |
| 개인정보       | 이메일, 전화번호 등                         |

탐지 시 사용자에게 경고한다.

```txt
선택한 파일에 민감정보로 보이는 문자열이 포함되어 있습니다.
원격 Ollama로 전송하기 전에 내용을 확인하십시오.
```

# 20. 결론

이 프로젝트의 핵심은 **WinForms에서 Ollama를 호출하는 것 자체가 아니라, 어떤 파일을 어떻게 골라서 어떤 프롬프트로 넘길 것인가**다.

따라서 1차 버전은 다음 목표에 집중하는 것이 맞다.

```txt
1. 프로젝트 폴더 선택
2. 파일 목록 스캔
3. 필요한 파일 선택
4. 사용자 질문 입력
5. Local / Remote Ollama 선택
6. Ollama API 호출
7. 답변 출력
8. 보안 경고와 오류 처리
```
